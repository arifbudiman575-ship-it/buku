## BAGIAN 2 — A/B/C Testing Methodology

### 2.1. Apa yang di-test

**Variable yang di-test: HOOK STYLE**

| Post | Hook style | Asal hook |
|---|---|---|
| **Post A** | **Contrarian** ("X akan obsolete...") | Hook Bank #3 + voice buku |
| **Post B** | **Confession** (origin story Rp 847K) | Hook Bank #9 + Prolog buku |
| **Post C** | **Callout** ("BERHENTI mengoleksi...") | Hook Bank #14 + Bab 1 buku |

### 2.2. Apa yang DIKONTROL (sama untuk ketiga post)

| Variable | Nilai (sama untuk A, B, C) |
|---|---|
| Topic core | Anti-tools-obsession (sistem > tools) |
| Length | 420–490 karakter (single post Threads) |
| CTA | Komen "ARSITEK" → 7-Day Challenge |
| Voice | "Anda" formal, tenang |
| Frase signature di akhir | Ada (1 baris quotable) |
| Posting time slot | **06:45–07:00 WIB** (sama setiap hari) |
| Posting day | 3 hari berturut-turut, hari kerja |
| Hashtag | TIDAK pakai (Threads tidak butuh) |

### 2.3. Mengapa methodology ini (bukan parallel test)

**Parallel test (3 post di hari yang sama)** tidak cocok untuk akun starting from zero karena:
- Audience belum cukup besar untuk dibagi 3
- Cannibalization — orang yang sudah engage Post A mungkin tidak engage Post B
- Algoritma Threads tidak bisa fair-split traffic ke 3 post baru sekaligus

**Sequential test (3 post, 3 hari berturut-turut, slot waktu sama)** lebih akurat karena:
- Setiap post dapat full attention dari algorithm "freshness boost"
- Time slot sama → menghilangkan bias jam posting
- 3 hari berturut-turut → algoritma masih melihat akun konsisten (positive signal)
- Limitasi: hari yang berbeda (Sen vs Sel vs Rab) bisa beda audience behavior — kita catat ini sebagai noise

### 2.4. Posting schedule (lock — jangan ubah)

| Hari | Tanggal | Jam posting | Post |
|---|---|---|---|
| **Senin** | (isi tanggal) | 06:45 WIB | Post A — Contrarian |
| **Selasa** | (isi tanggal) | 06:45 WIB | Post B — Confession |
| **Rabu** | (isi tanggal) | 06:45 WIB | Post C — Callout |

Setelah Post C tayang Rabu pagi, **tunggu 72 jam tanpa post baru di Threads**. Ini critical untuk testing accuracy — kalau Anda post hal lain di antara, akan muddy the data. Anda boleh tetap engage komen + DM. Yang dilarang: posting konten baru.

## BAGIAN 5 — Decision Rules (evaluasi setelah 72 jam)

### 5.1. Hierarki metric (yang penting → kurang penting)

> **Aturan:** Kita BUKAN menentukan winner berdasarkan views (vanity metric). Kita tentukan berdasarkan **konversi ke audience yang benar**.

| Tier | Metric | Bobot |
|---|---|---|
| **Tier 1 — Primary** | DM "ARSITEK" + new followers berkualitas | **60%** |
| **Tier 2 — Secondary** | Profile visits + reply substansif | **25%** |
| **Tier 3 — Tertiary** | Likes + reposts + views | **15%** |

### 5.2. Skor gabungan (composite score)

Hitung untuk setiap post:

```
SKOR_POST = (DM × 10) + (Followers_baru × 5) + (Reply_substansif × 3) + (Likes × 0.5)
```

Multiplier dipilih supaya **kualitas konversi lebih berbobot dari kuantitas perhatian**.

**Contoh perhitungan (data fiktif):**

| Post | DM | Followers | Reply substantif | Likes | **Skor** |
|---|---|---|---|---|---|
| A | 12 | 25 | 5 | 80 | (120) + (125) + (15) + (40) = **300** |
| B | 25 | 40 | 8 | 60 | (250) + (200) + (24) + (30) = **504** |
| C | 8 | 15 | 4 | 100 | (80) + (75) + (12) + (50) = **217** |

**Pemenang:** Post B (Confession) — skor tertinggi.

### 5.3. Decision rules (apa yang dilakukan setelah hitung skor)

| Selisih skor pemenang vs runner-up | Aksi Minggu 2 |
|---|---|
| **>30%** (selisih jelas) | **Scale winner.** Minggu 2 produksi 3 post lagi dengan hook style yang sama, topic berbeda. Validasi pattern. |
| **15–30%** (selisih moderat) | **Lean ke winner, tapi tetap test.** Minggu 2 = 2 post hook winner + 1 post hook style baru (yang belum di-test, mis. Question/List). |
| **<15%** (hasil tidak conclusive) | **Test lagi dengan variabel berbeda.** Mungkin masalahnya bukan hook style, tapi audience belum cukup besar atau topic kurang menarik. Minggu 2 = test FORMAT (single vs thread vs carousel). |
| **Semua post under-perform** (DM <5 ketiganya, followers <30 total) | **Audit fundamental.** Mungkin: (a) bio belum jelas, (b) profile picture tidak mendukung, (c) audience target salah. Pause posting baru, fix fundamentals dulu. |

### 5.4. Threshold "under-perform" (alarm bel)

Untuk akun starting (followers <500), benchmark realistis 72 jam:

| Metric | Under-perform | Acceptable | Strong |
|---|---|---|---|
| Views | <500 | 500–2.000 | >2.000 |
| Likes | <10 | 10–50 | >50 |
| DM "ARSITEK" | <3 | 3–10 | >10 |
| New followers | <10 | 10–30 | >30 |

Kalau **2 dari 3 post** masuk kategori "under-perform" pada metric utama (DM + Followers), aktifkan rule "audit fundamental" di 5.3.

### 5.5. Catatan untuk skenario "false negative"

Mungkin satu post tidak performa baik **bukan** karena hook-nya jelek, tapi karena:
- Hari posting bertepatan dengan event besar (mis. Lebaran, election, breaking news)
- Threads algorithm sedang glitch
- Kondisi personal (Anda tidak engage komen)

**Mitigasi:** Catat "konteks eksternal" di setiap hari posting. Kalau ada outlier eksternal jelas, repeat test post itu di minggu lain.
